# tools/nix - flake, dev shell, and the sandbox-host NixOS guest

- TrueNAS is `mother-brain.ghoul-basilisk.ts.net` (24.10.2); its authenticated web shell runs as `truenas_admin` and can use `midclt` without sudo. VM `sandbox_host` (ID 8; TrueNAS disallows hyphens in VM names) was created with 1 socket / 8 cores / 1 thread, host passthrough, 48 GiB fixed RAM, UEFI, UTC, autostart, and VirtIO NIC on `enp4s0f1` (the NAS default route and existing forge VM interface). Host `kvm_amd` nested virtualization is enabled. <source: live TrueNAS UI and middleware checks, 2026-09-21>
- VM 8 disks are `/dev/zvol/cache/zvols/sandbox_host-f5uoh5` (120 GiB OS), `sandbox-host-work` (512 GiB), `sandbox-host-cache` (128 GiB), and `sandbox-host-artifacts` (128 GiB), with the latter three under the same zvol parent. The `cache` pool is a healthy mirror of two T-FORCE SATA SSDs, not NVMe; about 535 GiB remains available after these reservations. <source: live vm.device.query, pool.query, disk.query, and pool.dataset.query, 2026-09-21>
- Initial provisioning installed the pinned flake successfully at `/etc/nixos` using disko and `nixos-install --no-root-passwd`. The installer guest received `192.168.12.243`, exposed `/dev/kvm`, and saw all four disks. The installed runtime passed `msb doctor` in nixos-enter (svm, libkrunfw, and read/write KVM access). Tailscale enrollment succeeded on the personal `zico-io.github` tailnet as `sandbox-host.ghoul-basilisk.ts.net` (`100.99.48.15`) with `tag:sandbox-host`. The VM returned online after poweroff and disk-first startup (CD-ROM order 2000). SSH reaches Tailscale but is denied by its SSH policy; installed-boot service verification remains pending that rule. Verified NixOS 26.05 installer media lives at `/mnt/cache/sandbox-media/nixos-minimal-26.05.iso` (VM CD-ROM device 35). <source: live guest console, successful nixos-install exit, TrueNAS middleware, and post-restart SSH attempt, 2026-09-21>

- sops-nix is wired conditionally: `hosts/sandbox-host/default.nix` enables it only if `secrets/sandbox-host.yaml` exists, so a fresh checkout still evaluates and CI stays green before any secret is created. The host decrypts with its own SSH host key via `sops.age.sshKeyPaths`, which means the host must exist before its secrets can be encrypted to it. <source: hosts/sandbox-host/default.nix + secrets/README.md, 2026-09-21>

- The repo is a flake (`flake.nix`, nixpkgs `nixos-26.05` + disko + sops-nix). Outputs: `nixosConfigurations.sandbox-host`, `nixosModules.tailnet`, `packages.{botfiles,jev-cli,t3code}`, `devShells.default`, and the botfile `checks`. home-manager, durable-pi and microsandbox were removed when the host became a pool node <source: flake.nix, 2026-10-27>
- sandbox-host is a **k3s agent of the home cluster yggdrasil** (gitlab percs/yggdrasil, servers 192.168.12.20-22, API VIP .30), labeled and tainted `pool=sandbox` (`hosts/sandbox-host/k3s.nix`). It hosts no logins: users reach sandboxes only through the `sandbox` gateway, which yggdrasil runs <source: hosts/sandbox-host/k3s.nix, 2026-10-27>
- Sandboxes run under the containerd runtime `kata`, from nixpkgs `kata-runtime` (qemu, with kata-images and virtiofsd paths patched in by the package). k3s's containerd finds `containerd-shim-kata-v2` through `systemd.services.k3s.path`, and the runtime's `ConfigPath` points at the package's `configuration-qemu.toml`. kata-deploy is avoided because it rewrites a declarative host from a DaemonSet <source: nixpkgs pkgs/by-name/ka/kata-runtime, 2026-10-27>
- The nixpkgs pin has `k3s_1_36` = 1.36.3 against servers on 1.36.5. An agent older than its control plane is inside skew policy, never newer <source: nix eval, 2026-10-27>
- The k3s join uses a bootstrap token from `k3s token create`, sops key `k3s-token`, which can only join agents. Without `secrets/sandbox-host.yaml` the host still evaluates, with a k3s "token should be set" evaluation warning <source: hosts/sandbox-host/default.nix, 2026-10-27>
- Firewall: `tailscale0`, `cni0` and `flannel.1` are trusted, kubelet 10250/tcp and flannel VXLAN 8472/udp are accepted only from the three servers, reverse-path filtering is loose, and SSH is never opened on the LAN. Break-glass access is tailnet node `sandbox-pool-1` (`tag:sandbox-pool`) with user `admin`; recovery when tailscale is down is the TrueNAS VNC console <source: hosts/sandbox-host/k3s.nix + modules/tailnet.nix, 2026-10-27>
- The 512 GiB work disk is mounted at `/var/lib/sandboxes`, the root of yggdrasil's `local-sandbox` local-path StorageClass for persistent sandbox homes <source: hosts/sandbox-host/disko.nix, 2026-10-27>
- T3 Desktop and the T3 server must run the same version to pair: a `0.0.46-nightly` desktop against a `0.0.45` server fails with `UnknownBootstrapCredentialError` / HTTP 401 at `/oauth/token`. The sandbox image (yggdrasil `services/sandbox/image`) pins t3code to the desktop's version for this reason <source: live pairing reproduction 2026-10-11; carried over 2026-10-27>
- The 2026-10 "ssh sandbox-host times out" outage: the host's tailscaled was logged into the **work** tailnet (`sandbox-host.dragon-draco.ts.net`, left over from the unmerged second-tailnet branch), so from the home tailnet the name resolved to the LAN IP, where the firewall drops 22. NixOS `tailscaled-autoconnect` only uses `authKeyFile` when the daemon is not already Running, so moving tailnets needs `tailscale logout` + `tailscale up --reset --auth-key=file:...` <source: journalctl + tailscale status via k3s node debug pod, 2026-10-27>
- With no tailnet and no password, the way in is `nixosConfigurations.rescue`: build the ISO, attach it to VM 8 as a CD-ROM with boot `order` below the OS disk (`midclt call vm.device.update <id> '{"dtype":"CDROM","order":1000,"attributes":{"path":...}}'` - `dtype` is top-level, not in attributes), `vm.restart`, then `ssh root@192.168.12.243`. Restore the device to the installer ISO at order 2000 afterwards <source: rescue of sandbox-host, 2026-10-27>
- Once the host is a k3s node, `kubectl debug node/sandbox-host --profile=sysadmin` + `chroot /host` is a root shell that needs neither the tailnet nor the LAN firewall <source: 2026-10-27>
