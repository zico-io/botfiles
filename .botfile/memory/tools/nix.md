# tools/nix - flake, dev shell, and the sandbox-host NixOS guest

- The repo is a flake (`flake.nix`, nixpkgs `nixos-26.05` + disko + sops-nix). Outputs: `nixosConfigurations.sandbox-host`, `nixosModules.{microsandbox,tailnet}`, `packages.microsandbox` (Linux only), `devShells.default`, and `checks.botfile-{selfcheck,validate,budget-check}` which run the same gates CI runs. Deploy with `nixos-rebuild switch --flake .#sandbox-host --target-host sandbox-host.<tailnet>.ts.net`. <source: flake.nix, 2026-09-21>
- `sandbox-host` is the second sandbox backend, alongside (not replacing) the Apple `container` path in `sandbox/`: a NixOS guest on the bare-metal TrueNAS box (Ryzen 9 5900X / 128 GB) giving coding agents KVM microVMs over the tailnet. Hypervisor envelope it assumes: 8 cores, 48 GiB *fixed* memory (leave TrueNAS's minimum-memory field empty - ballooning plus nested microVMs is a bad pairing), UEFI, host CPU passthrough, nested virtualization ON, VirtIO disks and NIC. <source: hosts/sandbox-host/default.nix, 2026-09-21>
- microsandbox 0.7.2 is a **CLI only** - there is no `msb server`, no daemon, and no JSON-RPC/REST/MCP endpoint. The `msbserver` + `POST /v1/sandboxes` gateway described by older microsandbox docs is gone from the current release, so a tailnet HTTP job API would be a service we write, not something to wrap. Access today is Tailscale SSH onto the host plus `msb` directly. <source: `msb --help` / `msb --tree` run from the v0.7.2 release tarball, 2026-09-21>
- microsandbox is not in nixpkgs, so `pkgs/microsandbox.nix` packages upstream's release archive. The tarball is flat and holds exactly two files, `msb` and `libkrunfw.so.5.6.1`. `msb` does not list libkrunfw in its ELF NEEDED entries (it dlopens it by SONAME) and its stock RUNPATH is a literally-escaped `\$$ORIGIN` the loader cannot expand, so `appendRunpaths = [ "$out/lib" ]` is what actually makes the pair resolve; NEEDED libs are glibc plus `libcap-ng`. <source: readelf on the v0.7.2 linux-x86_64 tarball, 2026-09-21>
- `msb doctor` is the KVM preflight: it prints CPU virt + `/dev/kvm` status and exits non-zero when either is missing, so `microsandbox-preflight.service` runs it at boot and a hypervisor with nested virtualization switched off fails loudly there instead of at the first agent job. `MSB_HOME` (default `~/.microsandbox`) relocates all state; the module points it at the NVMe workspace disk. <source: `msb doctor` on a host without /dev/kvm, 2026-09-21>
- Access posture is deny-by-default: no LAN ports open, `trustedInterfaces = [ "tailscale0" ]`, SSH not firewall-opened, password auth off everywhere, and Tailscale SSH (`--ssh` + `--advertise-tags=tag:sandbox-host`) as the authentication boundary instead of a committed public key. Recovery when tailscale itself is down is the TrueNAS VNC console, which is why no LAN SSH hole exists. <source: modules/tailnet.nix, 2026-09-21>
- sops-nix is wired conditionally: `hosts/sandbox-host/default.nix` enables it only if `secrets/sandbox-host.yaml` exists, so a fresh checkout still evaluates and CI stays green before any secret is created. The host decrypts with its own SSH host key via `sops.age.sshKeyPaths`, which means the host must exist before its secrets can be encrypted to it. <source: hosts/sandbox-host/default.nix + secrets/README.md, 2026-09-21>
- Known gap, documented not hidden: `microsandbox.slice` (CPUQuota/MemoryMax/TasksMax) bounds only the units the module manages. Sandboxes started from an interactive session land in that user's slice instead, so the ceiling is a floor on host protection, not a total cap. There is also no TTL reaper yet. <source: modules/microsandbox.nix, 2026-09-21>
