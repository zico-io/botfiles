# tools/nix - flake, dev shell, and the sandbox-host NixOS guest

- TrueNAS is `mother-brain.ghoul-basilisk.ts.net` (24.10.2); its authenticated web shell runs as `truenas_admin` and can use `midclt` without sudo. VM `sandbox_host` (ID 8; TrueNAS disallows hyphens in VM names) was created with 1 socket / 8 cores / 1 thread, host passthrough, 48 GiB fixed RAM, UEFI, UTC, autostart, and VirtIO NIC on `enp4s0f1` (the NAS default route and existing forge VM interface). Host `kvm_amd` nested virtualization is enabled. <source: live TrueNAS UI and middleware checks, 2026-09-21>
- VM 8 disks are `/dev/zvol/cache/zvols/sandbox_host-f5uoh5` (120 GiB OS), `sandbox-host-work` (512 GiB), `sandbox-host-cache` (128 GiB), and `sandbox-host-artifacts` (128 GiB), with the latter three under the same zvol parent. The `cache` pool is a healthy mirror of two T-FORCE SATA SSDs, not NVMe; about 535 GiB remains available after these reservations. <source: live vm.device.query, pool.query, disk.query, and pool.dataset.query, 2026-09-21>
- Initial provisioning installed the pinned flake successfully at `/etc/nixos` using disko and `nixos-install --no-root-passwd`. The installer guest received `192.168.12.243`, exposed `/dev/kvm`, and saw all four disks. The installed runtime passed `msb doctor` in nixos-enter (svm, libkrunfw, and read/write KVM access). Tailscale enrollment succeeded on the personal `zico-io.github` tailnet as `sandbox-host.ghoul-basilisk.ts.net` (`100.99.48.15`) with `tag:sandbox-host`. The VM returned online after poweroff and disk-first startup (CD-ROM order 2000). SSH reaches Tailscale but is denied by its SSH policy; installed-boot service verification remains pending that rule. Verified NixOS 26.05 installer media lives at `/mnt/cache/sandbox-media/nixos-minimal-26.05.iso` (VM CD-ROM device 35). <source: live guest console, successful nixos-install exit, TrueNAS middleware, and post-restart SSH attempt, 2026-09-21>

- The repo is a flake (`flake.nix`, nixpkgs `nixos-26.05` + disko + sops-nix). Outputs: `nixosConfigurations.sandbox-host`, `nixosModules.{microsandbox,tailnet}`, `packages.{botfiles,t3code}` and `packages.microsandbox` (Linux only), `devShells.default`, and `checks.botfile-{selfcheck,validate,budget-check}` which run the same gates CI runs. Deploy with `nixos-rebuild switch --flake .#sandbox-host --target-host sandbox-host.<tailnet>.ts.net`. <source: flake.nix, 2026-10-04>
- microsandbox 0.7.2 is a **CLI only** - there is no `msb server`, no daemon, and no JSON-RPC/REST/MCP endpoint. The `msbserver` + `POST /v1/sandboxes` gateway described by older microsandbox docs is gone from the current release, so a tailnet HTTP job API would be a service we write, not something to wrap. Access today is Tailscale SSH onto the host plus `msb` directly. <source: `msb --help` / `msb --tree` run from the v0.7.2 release tarball, 2026-09-21>
- microsandbox is not in nixpkgs, so `pkgs/microsandbox.nix` packages upstream's release archive. The tarball is flat and holds exactly two files, `msb` and `libkrunfw.so.5.6.1`. `msb` does not list libkrunfw in its ELF NEEDED entries (it dlopens it by SONAME) and its stock RUNPATH is a literally-escaped `\$$ORIGIN` the loader cannot expand, so `appendRunpaths = [ "$out/lib" ]` is what actually makes the pair resolve; NEEDED libs are glibc plus `libcap-ng`. <source: readelf on the v0.7.2 linux-x86_64 tarball, 2026-09-21>
- `msb doctor` is the KVM preflight: it prints CPU virt + `/dev/kvm` status and exits non-zero when either is missing, so `microsandbox-preflight.service` runs it at boot and a hypervisor with nested virtualization switched off fails loudly there instead of at the first agent job. `MSB_HOME` (default `~/.microsandbox`) relocates all state; the module points it at the NVMe workspace disk. <source: `msb doctor` on a host without /dev/kvm, 2026-09-21>
- Access posture is deny-by-default: no LAN ports open, `trustedInterfaces = [ "tailscale0" ]`, SSH not firewall-opened, password auth off everywhere, and Tailscale SSH (`--ssh` + `--advertise-tags=tag:sandbox-host`) as the authentication boundary instead of a committed public key. Recovery when tailscale itself is down is the TrueNAS VNC console, which is why no LAN SSH hole exists. <source: modules/tailnet.nix, 2026-09-21>
- sops-nix is wired conditionally: `hosts/sandbox-host/default.nix` enables it only if `secrets/sandbox-host.yaml` exists, so a fresh checkout still evaluates and CI stays green before any secret is created. The host decrypts with its own SSH host key via `sops.age.sshKeyPaths`, which means the host must exist before its secrets can be encrypted to it. <source: hosts/sandbox-host/default.nix + secrets/README.md, 2026-09-21>
- Known gap, documented not hidden: `microsandbox.slice` (CPUQuota/MemoryMax/TasksMax) bounds only the units the module manages. Sandboxes started from an interactive session land in that user's slice instead, so the ceiling is a floor on host protection, not a total cap. There is also no TTL reaper yet. <source: modules/microsandbox.nix, 2026-09-21>
- sandbox-host gets `claude-code` and `codex` from `numtide/llm-agents.nix` (flake input `llm-agents`, exposed as `pkgs.llm-agents.*` by an overlay), not nixpkgs, which lags upstream. The input deliberately has no `nixpkgs.follows` so `cache.numtide.com` (configured in `nix.settings`) serves prebuilt binaries; bump with `nix flake update llm-agents`. Until that cache is in the host's nix.conf, a non-root build compiles codex from source (~15+ min). <source: llm-agents.nix README + host build, 2026-10-03>

- Warp's Codex plugin hooks use `#!/bin/bash` and failed on sandbox-host because NixOS provided only `/bin/sh`. `/etc/tmpfiles.d/agent-bash.conf` now creates `/bin/bash` pointing to `/run/current-system/sw/bin/bash` at boot; the host module also declares the compatibility link through `systemd.tmpfiles.rules`. All five installed Codex Warp hook commands subsequently exited 0 with empty stderr in the T3 environment. <source: direct PostToolUse reproduction, live tmpfiles application, hosts/sandbox-host/default.nix, and all-hook invocation checks, 2026-10-11>

- Durable Pi runs on sandbox-host as Home Manager user services from `modules/durable-pi.nix` (`homeManagerModules.durable-pi`): `dpi-backend` on 127.0.0.1:4780 reading `~/.dpi/backend.env`, and `dpi-hub` on 0.0.0.0:4781 with `tailnetAllow = [ "nico@bask.health" ]`. The hub's gate asks tailscaled's LocalAPI whois about each connection's source address, so identity comes from WireGuard, not headers; tagged nodes, loopback and the LAN get 403, and an unreachable tailscaled gets 503. `pkgs/durable-pi.nix` builds the three apps' node_modules with `importNpmLock.buildNodeModules`, so no npmDepsHash needs bumping. <source: modules/durable-pi.nix + live curl checks, 2026-10-12>
