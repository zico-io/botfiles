# tools/orchestration — multi-agent harness

- Fleets run on herdr (panes/tabs/status) + the agent-comms tool (rooms/DMs);
  herdr does placement and process, agent-comms does coordination. <source: orchestration/spawn.py, 2026-07-07>
- Hierarchy is capped at 3 layers, enforced by room membership: L1 orchestrator + L2 leads share `mission-<feature>`; each L2 lead + its L3 workers share `squad-<lead>`; the orchestrator never shares a room with a worker. <source: AGENTS.md orchestration protocol, 2026-07-07>
- `orchestration/spawn.py up <roster.json>` spawns the fleet (leads as tabs, workers as splits), launches each harness, and injects a bootstrap that registers the agent into agent-comms; `down <feature>` closes the workspace. Rooms are torn down by the orchestrator via agent-comms `destroy_room`. <source: orchestration/spawn.py, 2026-07-07>
- Supported harnesses: claude, codex, pi (launch templates in the `HARNESSES` map). Cross-harness comms requires the agent-comms wiring that `provision.sh` ensures: codex via `[mcp_servers.agent-comms]` (bridge `codex`), pi via the `npm:agent-comms` package, claude via `claude mcp` (bridge `claude-code`). There is no `pi` bridge. <source: provision.sh + `agent-comms bridge`, 2026-07-07>
- Roster schema and the orchestrator drive loop: `orchestration/roster.example.json`, `.claude/commands/spawn-team.md`. Modeled on github.com/disler/learning-cmux-with-agents (cmux → herdr, screen-scraping → agent-comms). <source: orchestration/, 2026-07-07>
- Spawning a claude agent needs `bypassPermissionsModeAccepted: true` in `~/.claude.json`, else the first-run "Bypass Permissions" dialog blocks startup and the agent never reaches ready. Setting the key by hand can be clobbered by a running claude rewriting the file; a one-time real accept persists it. <source: spawn.py smoke run + claude-code 2.1.197, 2026-07-07>
- `HARNESSES` ready/working strings are version-sensitive. For claude 2.1.197: ready match is `bypass permissions on` (old `for shortcuts` no longer prints), working match is `esc to interrupt`. Tune in the `HARNESSES` map if a banner changes. <source: orchestration/spawn.py, 2026-07-07>
- `launch()` confirms an injected bootstrap actually submitted (waits for the harness `working` marker) and re-sends Enter once if a freshly-split worker pane swallowed the submit newline. Without this, workers sit with the prompt typed but unsent. <source: orchestration/spawn.py, 2026-07-07>
- agent-comms co-located bridges share one in-memory mesh via a coordinator on `127.0.0.1:19876`; it is NOT federation (federation only carries presence + `federated:true` rooms, and the MCP `create_room` cannot set `federated`). Upstream 1.24.0 islanded peers under concurrent fleet startup. Fixed in fork `zico-io/agent-comms` branch `fix/mesh-concurrent-start-islanding` (init retry on EADDRINUSE, topology dispatch over data links, coordinator periodic resync) and deployed by overlaying the 3 compiled files onto `/opt/homebrew/lib/node_modules/agent-comms/dist/core/`; a `brew upgrade` overwrites the overlay. <source: fork commit ee9bc4d + mesh-store.ts, 2026-07-07>
