# tools/orchestration — multi-agent harness

- Fleets run on herdr (panes/tabs/status) + a per-mission **comms server** that
  agents reach with the `comms` CLI over TCP; herdr does placement/process, the
  comms server does coordination (rooms/DMs/status). comms is **one Rust binary**
  (`comms/`, built by `provision.sh`/Containerfile): `comms serve` is the server,
  every other subcommand is the client. <source: comms/ crate + orchestration/spawn.py, 2026-07-08>
- Hierarchy is capped at 3 layers, enforced by room membership: L1 orchestrator + L2 leads share `mission-<feature>`; each L2 lead + its L3 workers share `squad-<lead>`; the orchestrator never shares a room with a worker. <source: AGENTS.md orchestration protocol, 2026-07-07>
- One comms server per mission, started on the host by `spawn.py up` (binds `0.0.0.0:<ephemeral>`, Bearer-token auth). It is the single authority for every room, so killing it at teardown IS the room cleanup - there is no orphaned-squad-room class anymore. `up` records `comms_url`/`comms_token`/`comms_pid` in the per-mission `mission.json`; `down` reads that pid and SIGTERMs it (all rooms vanish), so `down` no longer pokes leads to `destroy_room` and there is no cleanup grace wait. The server is started **detached** (`start_new_session`, so it reparents to init and a Ctrl-C / pane close in the launching terminal can't kill it mid-mission - that silent death once stranded every agent on `comms wait`); its output goes to `comms.log` for post-mortem. State **persists to SQLite** (`comms.db` beside `mission.json`, passed via `comms serve --db`), which lets a *manual* mid-mission restart keep every room and message - but a fresh `up` **wipes** `comms.db` first, so a new mission never inherits a prior (interrupted) run's rooms/messages (a leftover db once booted fresh agents onto stale instructions). <source: orchestration/spawn.py comms_up/up/down + comms/ crate, 2026-07-08>
- `orchestration/spawn.py up <roster.json> [teams]` spawns the fleet (leads as tabs, workers as splits), starts the comms server, launches each harness, and injects a bootstrap that runs `comms join`/`create-room`/`send` for its room; it records a role->pane map in `mission.json`. `poke <feature> <role> [msg]` wakes an idle agent by that map. `status <feature>` prints mission health in one shot (comms server alive/dead + a restart line, container, agents, per-room message counts + last message) - it replaces the manual ps/lsof/container/comms dig used to diagnose a stall. `down <feature>` kills the comms server and closes the workspace; `mission_down` times out a wedged `container rm` and force-kills the VM runtime by uuid. `up` is **transactional**: any failure tears down the partial VM/workspace/server instead of orphaning them. <source: orchestration/spawn.py, 2026-07-08>
- A roster is a **catalog** of teams, not a fixed fleet: `up`'s optional 3rd arg is a comma list of lead roles to spawn (each lead's workers come with it); omitting it spawns the whole roster. The orchestrator picks the minimum teams a mission needs (`spawn-team.md` step 0) rather than always booting every team - selection is `select_leads()`, an unknown team errors with the available list. <source: this change, 2026-07-08>
- Agent identity is the `COMMS_AGENT` env var, injected per `container exec` (with `COMMS_URL`/`COMMS_TOKEN`) by `sandbox_wrap`; the server upserts an agent on its first call (implicit register, no register step). Because `comms` is a plain binary on PATH (guest copy built in the Containerfile's `rust:1-slim` multi-stage step; host copy built by `provision.sh` and symlinked to `~/.local/bin` - no sudo, on PATH - so `spawn.py up` finds it by name), any harness with a shell can coordinate - no per-harness MCP bridge, no `provision.sh` MCP wiring. <source: orchestration/spawn.py launch/sandbox_wrap + sandbox/Containerfile, 2026-07-08>
- Each mission VM gets **8 CPU / 12 GB** (`mission_up` `-c`/`-m`; overridable via `MISSION_CPUS`/`MISSION_MEMORY`). Apple `container` defaults to 4 CPU / 1 GB, which thrashed the moment agents ran cargo and wedged the whole container daemon. The sandbox image ships a **full Rust toolchain** (rustup stable + rustfmt/clippy/llvm-tools-preview, build-essential, and cargo-deny + cargo-llvm-cov via cargo-binstall) so agents run the entire fmt/clippy/test/deny/coverage gate in-guest; before this the runtime image had no toolchain and agents stalled trying to install rustup inside a 1 GB VM. Bake the tools a mission's repo needs into the image, don't make agents install them. <source: sandbox/Containerfile + orchestration/spawn.py mission_up, 2026-07-08>
- comms has **push** via `comms wait <room>`: a blocking long-poll that returns the instant a message lands (server holds the request open on a Condvar, 2s backstop, default 120s timeout). The bootstrap tells agents to BLOCK on `comms wait` and forbids shell poll loops (`while`/`for`/`sleep` around comms) - those loops are the failure mode that starved the first real mission. `poke` is still the wake for a pane NOT currently blocked on wait (idle between tasks): `spawn.py poke <feature> <role>` is a herdr pane-run nudge, not a comms message, so it doesn't breach room hierarchy; in sandbox mode only the host reaches herdr, so pokes originate from the orchestrator. <source: comms/ crate wait + spawn.py bootstrap/poke, 2026-07-08>
- comms `read` and `wait` are **consuming**: each advances the caller's per-room cursor, so a second call returns only newer messages. To monitor or inspect a room *without* eating it, use `comms peek <room>` (non-consuming; `read --since 0` also shows all but still advances the cursor). This is a footgun - monitoring a room with `read` silently consumed the orchestrator's own view and looked like state loss - which is why `peek` exists; `spawn.py status` uses it. <source: comms/ crate op_read peek flag + spawn.py status, 2026-07-08>
- **Remote-wake gap:** herdr `poke` is PTY/pane-local to the host, so it can only wake agents whose panes are on the host (today: local-VM agents). The comms server is network-reachable, so remote containers could *coordinate*, but *waking* a remote idle agent (herdr can't reach remote panes) is out of scope. **Ingress precondition:** a remote container must be able to route to the host's advertised `comms_url` (firewall/NAT/VPN); `COMMS_ADVERTISE_HOST` overrides the auto-detected primary IP. <source: design decision, 2026-07-08>
- Roster schema and the orchestrator drive loop: `orchestration/roster.example.json`, `.claude/commands/spawn-team.md`. Modeled on github.com/disler/learning-cmux-with-agents (cmux → herdr). <source: orchestration/, 2026-07-08>
- Spawning a claude agent needs `bypassPermissionsModeAccepted: true` in `~/.claude.json`, else the first-run "Bypass Permissions" dialog blocks startup and the agent never reaches ready. Setting the key by hand can be clobbered by a running claude rewriting the file; a one-time real accept persists it. <source: spawn.py smoke run + claude-code 2.1.197, 2026-07-07>
- `HARNESSES` ready/working strings are version-sensitive. For claude 2.1.197: ready match is `bypass permissions on` (old `for shortcuts` no longer prints), working match is `esc to interrupt`. Tune in the `HARNESSES` map if a banner changes. <source: orchestration/spawn.py, 2026-07-07>
- Submitting text into a Claude TUI pane: `herdr pane run <pane> <text>` types AND submits reliably (used by launch/poke). To submit an already-typed buffer, `herdr pane send-text <pane> "\r"` (carriage return = the real Enter). `send-keys <pane> Enter` does NOT submit the Claude TUI (only raw shells), and a bare `\n` submits only short inputs, not the long bootstrap - use `\r`. `spawn.py submit()` waits for the `working` marker and resends `\r` once if the pane swallowed the submit; a still-missing marker after the resend is **non-fatal** (the agent is almost certainly already running a foreground command - e.g. a `comms` call - whose TUI footer is "ctrl+b to run in background", not the idle "esc to interrupt" we match), so one slow worker no longer aborts the whole `up`. <source: spawn.py submit + teams-mission spawn failures, 2026-07-08>
