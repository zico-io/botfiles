# forge - gates, then push

- `bin/forge push` runs devenv tasks `forge:{format,lint,typecheck,unit,integration}` cheapest first after `forge:ready`, stops at the first failure, and pushes only on success; gate commands live in each repo's devenv.nix, written by `skills/forge-env` <source: forge build session, 2026-11-04>
- Gate contract: env `FORGE_MERGE_BASE` (SHA), `FORGE_BASE` (branch), `FORGE_CHANGED_FILES` (path to a newline-separated list of ACMR paths since the merge base); exit 0 passes; tasks run from the repo root <source: forge build session, 2026-11-04>
- devenv 2.1.2 `devenv tasks run` deletes the running native manager's `native-manager.pid` and `native.sock` under `.devenv/run/processes/`; the daemon and its services keep running but `devenv processes list/down` report "No process manager is running", so forge reads the pid after `processes wait` and SIGTERMs it at teardown <source: reproduced in /private/tmp/forge-e2e with devenv 2.1.2, 2026-11-04>
- devenv 2.1.2 drops task stdout when it detects an AI agent (`CLAUDECODE`, `AI_AGENT`, `OPENCODE_CLIENT`), even with `--show-output`; `DEVENV_NO_AI_AGENT=1` turns that off; stderr always shows <source: reproduced with devenv 2.1.2, 2026-11-04>
- devenv 2.1.2: `devenv up -d` with no `processes` exits 1 with "No processes defined"; an unknown task exits 1 with "Task does not exist"; tasks inherit the caller's env; allocated ports (`ports.<n>.allocate`, also `processes.mysql.ports.main`) stay stable across later `tasks run` while the service holds them <source: reproduced with devenv 2.1.2, 2026-11-04>
- The process ready probe option is `processes.<name>.ready` (`exec`, `http.get`, `notify`), not `ready_probe` <source: devenv 2.1.2 eval and devenv.sh/processes, 2026-11-04>
- No merge-base rerun to classify failures as pre-existing: diff-scoped gates select nothing at the merge base, so a rerun would pass every failure; use `--skip <gate> --reason` instead <source: forge build session, 2026-11-04>
- `hooks/forge-push-guard.py` denies bare `git push` in Claude Code (PreToolUse, Bash matcher); `git -C dir push` and `command git push` bypass it on purpose; `bin/botfile wire --tool claude` registers it in `~/.claude/settings.json` and `wire` links `~/.local/bin/forge` <source: forge build session, 2026-11-04>
